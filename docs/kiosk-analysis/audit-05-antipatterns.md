# Kiosk Anti-Pattern Audit

Surface: `/kiosk` — `src/app/kiosk/**`, `src/components/kiosk-*.tsx`, `src/app/globals.css`, `DESIGN.md`, `PRODUCT.md`.
Method: full read of every kiosk route/component file plus the shared `globals.css` (including all 15 `[data-kiosk-theme]` blocks), cross-checked against `DESIGN.md`'s own component/typography contract and the sibling `/smarthome` `ha-*.tsx` panels kiosk-hub explicitly mirrors. No browser session was run for this pass, so anything that can only be confirmed by rendering (real overflow at a given breakpoint, live contrast) is called out as unverified rather than asserted as a hit.

## Score (0-4)

**3 — mostly clean, subtle tells only.** One real, citable accessibility-motion gap and two small polish nits. Nothing that reads as templated or generated; the deviations found are inconsistencies within an otherwise very deliberate system, not slop patterns.

## Verdict

**Generated-looking? No.** Nothing here matches the AI-slop tells checklist — no side-stripe cards, no gradient text, no hero-metric tiles, no numbered scaffolding, no arbitrary z-index escalation, no nested cards in the pejorative sense. The component vocabulary (buttons, panels, dots, badges) is drawn from one documented system and reused correctly almost everywhere, including in the harder cases (a 15-theme catalog that stays architecturally uniform, a crash boundary with real recovery logic, honest stale/empty/unconfigured states with real explanatory copy).

**Product-register trust test: pass.** Someone fluent in Home Assistant, Apple Home, or a Nest/Echo Show display would recognize every idiom here as native to the category — the tile grid for lights/switches, the ring-gauge timer, the wall clock face, the "no lights configured yet" teaching copy. The one place a fluent user could actually pause is the crash screen's Reload button, which is subtly off-vocabulary (see below) — everywhere else the surface holds together.

## Component-state gaps

Coverage is unusually complete for a kiosk surface — most interactive components carry default/hover/focus/active/disabled, and the ones that skip a "pending" visual (see below) do so for a documented reason rather than by omission.

- **`ToggleTile` (`kiosk-hub.tsx:187-243`)** has default, hover, focus-visible, active-scale and disabled, but never receives `ha.isPending(...)` — unlike `SceneTile`, which does. The file's own thesis comment explains the optimistic-update contract (state flips instantly, a failed request reverts and surfaces `error`), so the omission is deliberate, not a half-shipped state. Worth noting only because a rapid double-tap during the in-flight window could send two toggle requests before the optimistic flip settles — a possible functional edge case, not a visual anti-pattern.
- **`KioskAppearance` theme chips and layout segmented control** — no loading/error state needed (pure client-side, synchronous), correctly omitted.
- **`KioskAdminPanel`** covers loading ("loading containers…"), error ("Docker unreachable: …"), and empty ("no containers found") — complete set.
- **`KioskHub`/`KioskDisplay`** both distinguish "unconfigured", "unreachable" (with and without a last-known-good payload via `StaleTag`), "unauthorized", "empty", and "loading" as five genuinely different states with real copy — this is the strongest state coverage in the audit.
- **Skeletons vs. spinners**: `HubSkeleton` and `WeatherSkeleton` correctly use `animate-pulse` placeholder blocks, not spinners, for section-level loading — compliant with the DESIGN.md rule. The one spinner in scope (`Loader2` inside the voice mic button, `kiosk-voice.tsx:164`) is an icon-state change on an already-visible control mid-action, not a spinner substituting for a skeleton — a defensible, different use.

## Motion review

- Durations in scope: `kiosk-pin-shake` 420ms, `voice-mic-pulse` 1.6s (looped), `log/rail-arrival` 1100ms (not kiosk-specific), status-dot `pulse` 1.6s/0.9s (looped). The one-off shake and mic pulse sit in a reasonable range for what they're signaling (a wrong-PIN jolt, a "listening" breathing ring); the looped status-dot pulse is a deliberate, restrained attention device per `DESIGN.md`'s own rule ("pulsing is reserved for the two states that want you to look").
- Easing: `cubic-bezier(0.16,1,0.3,1)` (settle) and `cubic-bezier(0.36,0.07,0.19,0.97)` (shake) throughout — no bounce/elastic curves anywhere in scope.
- **`prefers-reduced-motion` gap (P1, real finding):** `.dot-unhealthy` and `.dot-restarting` (`globals.css:94-103`, `@keyframes pulse` at `:120-124`) animate `infinite` with **no reduced-motion branch anywhere in the stylesheet** — the four other authored animations in the file (`kiosk-pin-shake`, `voice-mic-pulse`, `log-arrival`/`rail-arrival`, `net-sweep`) all get one, this one doesn't. It renders on the kiosk itself: `KioskHealth` (`kiosk-health.tsx:41`, all four count items reuse the same `dot` classes) and every container row in `KioskAdminPanel` (`kiosk-admin-panel.tsx:22`, via `stateDotClass`) will pulse indefinitely for a container in the `unhealthy` or `restarting` state regardless of the visitor's motion preference. This is the one place the surface's own stated rule ("gate every authored animation behind `prefers-reduced-motion`… everywhere") isn't followed, and it's exactly the kind of always-on, indefinite animation that rule exists to catch.
- Everything else with motion in kiosk scope (`kiosk-pin-shake`, `voice-mic-recording`, `KioskAttentionCard`'s entrance fade) correctly branches on `motion-reduce:`/the media query.

## Findings

1. **P1 — Status-dot pulse has no `prefers-reduced-motion` branch.** `globals.css:94-103` (`.dot-unhealthy`, `.dot-restarting`) and `:120-124` (`@keyframes pulse`). Affects `kiosk-health.tsx:41` and `kiosk-admin-panel.tsx:22` directly. Every other authored animation in the same file is gated; this one was missed. Real accessibility gap, not a nitpick — see Motion review above.

2. **P3 — Crash-screen Reload button is off the kiosk's button vocabulary.** `src/app/kiosk/error.tsx:133` uses `h-14 … rounded-lg …` where every other primary accent button in kiosk scope (e.g. `kiosk-timers.tsx:495-501`'s Start button, `kiosk-admin-panel.tsx:66-72`'s Dashboard/Lock buttons, `kiosk-voice.tsx`'s Stop-speaking button) uses `h-11 … rounded-md …`. Same tint construction (`border-accent/30 bg-accent/10 text-accent hover:bg-accent/20`), different corner radius and height — a single control that looks subtly different from its own siblings, on the one screen (a crash) where trust matters most. Minor severity because it's a rare-to-see screen, but it's the one place in the audit where the "same action looks different in two places" check actually finds something.

3. **P3 — `chrome` theme's mono face silently borrows `aerogel`'s font variable.** `globals.css:737`: `--font-mono: var(--font-t-aerogel-mono), ui-monospace, monospace;` inside `[data-kiosk-theme="chrome"]`. Every other theme either defines its own mono font (`fChromeSans` exists in `kiosk-theme.tsx:78` but no `fChromeMono` was ever declared) or deliberately falls back to the system stack. Reads like a copy-paste seam from drafting the block off the Aerogel one rather than an intentional cross-theme reference — worth a follow-up to either give Chrome its own mono face or fall back to `ui-monospace` like a theme that has no opinion on mono would.

## Genuinely good

- **The status-dot system** (`globals.css:82-118`): glow only on states that should draw the eye, a hollow ring instead of a fifth hue for `paused`, colour strictly earned by a real threshold. This is the strongest, most disciplined idiom in the whole surface and it's applied identically everywhere a state needs to be shown.
- **`KioskAttentionCard`** (`kiosk-attention.tsx`): "silence is the payload" — renders nothing at all 99% of the time and one plain sentence when something's actually wrong. Exactly the right call for a wall display, and a real alternative to the reflexive toast/banner pattern.
- **The 15-theme catalog** (`kiosk-theme.tsx`, `globals.css:342-803`): genuinely differentiated by real ideas (CRT scanlines, risograph misregistration, neumorphic emboss, neo-brutalist offset shadows, Swiss International Style) rather than hue-shifts of one template, while staying on one architectural mechanism (`.panel`/`@theme` token overrides) throughout. Rare to see this much real variety without it degrading into a grab-bag — worth calling out as unusually well-executed, with the one seam noted above.
- **`KioskSky`** (`kiosk-sky.tsx`): ambient ground tint driven by real solar position and cloud cover from the weather API, capped at ~0.10 opacity, with a documented stacking-context explanation for why it has to mount where it does. Technically careful atmosphere, not decoration for its own sake.
- **Honest stale/empty/unconfigured states** across `KioskHub`, `KioskDisplay`, and `KioskStatusStrip` — real explanatory copy ("Connect it in Settings → Integrations, and your lights, scenes and climate appear here"), a shared `StaleTag` for "this is a last-known-good reading," and a clear distinction between "quiet because nothing's wrong" and "unreachable."
- **`error.tsx`'s self-healing crash ladder** — auto-reset up to 3 times, then a full reload, then stop and hand control to a human, all tuned for a screen nobody stands in front of to click things. A genuinely bespoke solution to an operational problem specific to this device, not a generic error boundary.
